## 3. 单机版 v0.1 范围（已实现）

### 3.1 保留的治理底线（08 §9.1 承诺兑现情况）

| 底线 | v0.1 实现 |
|---|---|
| 试用/正式分离（BR08） | 每条提示词独立维护"正式版"与"试用版（未考试）"指针；试用版处处带"未考试"角标 |
| 所有调用进账本（BR09） | 每次模型调用记录时间/用途/tokens/估算费用，"花费与记录"页可查 |
| 成本单旋钮（08 M4） | 每轮优化最多调用次数（默认 40），到顶自动停；可切换为金额上限（需先填单价） |
| 不伪造提升（BR12） | 结论由代码按配对统计计算；样本少固定显示"只能当参考"；无提升如实显示 |
| 盲评独立（P06/R10） | 对比页左右内容打乱、不显示版本身份，两边都评完才"揭晓" |
| 人工判断优先（07 R02/取舍B） | v0.1 全部质量判断来自人工（能直接用/改改能用/不能用/说不上来），无 AI 评审 |
| unknown 合法（BR04） | "说不上来"永远可选，不计入通过也不静默删除，在结论中单列 |

### 3.2 主流程（表单向导，全程无对话、无模板词汇）

```
新建优化：贴提示词 → 贴2—8个真实例子 → 看现在的水平（逐份标"能不能用"+可填"最要紧的问题"）
  → 一句话概括要解决的问题 → 生成改进版（可手动修改） → 左右盲评比一比 → 大白话结论
  → 存为试用版（标记：未考试）
用一用：贴今天的输入 → 用正在使用的版本出结果 → 点反馈（直接用了/改了改/没用）
  → 输入自动存进例子池（数据飞轮）
考个试：用攒的新例子（建议≥20份）对 正式版vs试用版 做匿名配对比较
  → 配对统计结论（"碰运气概率"<5% 才说"确实更好"） → 通过后手动点"转正"，随时可回滚
```

### 3.3 技术形态

- 纯 Python 标准库（http.server + sqlite3 + urllib），**零 pip 依赖**；Windows + Python 3.10+ 即可。
- 双击 `启动.bat` → 自动起本地服务并打开浏览器（127.0.0.1，仅本机回环）。
- 数据全部存本机 `data/lab.db`；API 密钥只存本机数据库，不出网（仅发往用户配置的模型接口）。
- 兼容 OpenAI 风格 `/v1/chat/completions` 接口，模型名与接口地址由用户在"设置"配置一次。

### 3.4 v0.1 明确不做（后续按需加）

GEPA 自动搜索多候选、AI 评审与校准、封存测试集与一次绑定、多人协作、备份恢复工具、自动通知。替代关系：GEPA 多候选 → 一次有针对性改写（07 §20.4 本就要求与"一次改写"对照）；封存集 → "考试只用没用过的新例子"轻量规则＋用途记录；校准 → 全人工判断。

### 3.5 已知限制（如实声明）

- 单用户、无登录鉴权（仅本机回环监听；不要将端口暴露到局域网/公网）。
- 统计结论基于配对符号检验的精确二项计算，样本少于 15 份一律显示"只能当参考"。
- 金额上限依赖单价准确性；单价未填时只允许"次数上限"模式。
- v0.1 未经真实用户测试；08 §8 的 5 人测试协议在可用后执行。

## 5. 实施结果（2026-10-05 当日完成）

- **端到端测试：37 项断言全部通过**（模拟模型接口下走完：贴提示词→例子→基线生成→人工评价→AI改写→盲评配对→结论→存试用版→日常使用与反馈回流→考试（基线自动衔接新版）→考过例子复用拦截→无验证转正需强制确认→次数上限自动暂停→提高单轮上限续跑→账本完整）。
- **UI 浏览器实测**：首页/新建优化/提示词详情/考试结果/设置页渲染正常；全程无英文阻断、无方法论术语泄漏（验证过界面文案不含"数据集/评价器/封存/校准"等词）；正式/试用（未考试）徽章全页常驻。
- 测试中发现并修复的缺陷：考试流程基线→新版的衔接线程拿不到运行锁导致卡死（改为锁释放后再衔接）；盲评的每边"能不能用"评级未落库导致结论统计为 0（提交时同步写回）；小样本 6:0 全胜满足统计显著即显示可转正（增加"至少 15 份"硬门槛）；单轮上限为创建时快照，暂停后无法提额（新增运行级提额接口）；结论文案双百分号。
- 测试后已清空 data 目录：用户首次启动为全新空状态（符合 D4 无示例项目）。
