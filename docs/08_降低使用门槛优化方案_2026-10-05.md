# 提示词自优化系统：降低使用门槛优化方案

版本：v1.0｜日期：2026-10-05｜性质：设计提案（未实施）
审查对象：2026-09-27 v2.0 需求与开发交付包 + 2026-10-04 审查与优化方案（07号文档）
关联：R05/R06（认知负担）、R14（首版范围）、R16（价值验证）；FR02/FR27/FR28/FR30；T03/T09

本方案回答一个问题：**怎样让一个不研究提示词优化的普通用户（教师、教研、编辑），像用普通 AI 产品一样用上这个系统，而不被部署、术语、成本和流程劝退。** 所有界面文案、金额、耗时均为设计示例；所有体验指标为待验证目标，不是已达成结果。

---

## 0. 一页结论

**诊断**：当前设计的门槛不是一层，是五道墙——部署墙、认知墙、语言墙、成本焦虑墙、时间墙。10-04 方案的"四个入口 + 按动作资格 + 双路径"解决了"找得到路"，但没有解决"进得来门"和"看得懂话"。

**核心方案**：三层体验架构 + 四个支撑体系。

- 三层体验：L0 演示层（零安装零注册试试看）→ L1 对话层（主界面，像聊天产品一样用）→ L2 工作台层（认真优化的向导流程）→ L3 实验室层（现有 14 页，给负责人和管理员）。
- 四个支撑：术语翻译体系（专业话变人话）、成本单旋钮（只管一个上限数字）、异步通知（系统找人，不是人等系统）、日常使用入口（产品嵌进每天的工作，顺带回收数据）。

**最大的一次结构改变**：把 PRD 里的"引导模式"从右侧面板升级为**产品主界面**。90% 的用户 90% 的时间只需要 L1；现有 14 页全部保留，降级为 L3，不删除、不重做。

**不改变的底线**：BR01—BR12 全部保留；"试用≠已验证"的标识永远在场；封存测试一次绑定；盲评独立性；所有结论带证据。**简化的是过程和语言，不是证据标准。**

**需要你拍板的三个决策**（见第 10 节）：① 试点期是否用一台服务器托管后台（普通用户拿到网址就用）；② 对话层是否作为首版主界面（影响 T03 的形态）；③ 首版是否只做一个任务模板的 L1 体验。

## 1. 为什么现在难：五道墙诊断

按用户实际遇到的先后顺序。每道墙都给出用户视角的原话感受——这是 5 人测试时要验证的假设，不是已证实的结论。

### 墙1 部署墙（在看到任何产品价值之前）

现状：本机部署要装 Docker Desktop、起 Linux 容器、配 API 密钥、跑 start.ps1。PRD 的 15 分钟首探目标（07 §18.9）明确把安装排除在外，但用户的挫败感从打开安装包就开始了。

用户感受："我就是想让 AI 帮我改个提示词，为什么要在我电脑上装 Docker？"

判断：这是**第一道也是最硬的一道墙**。对目标用户（教研、编辑），它的淘汰率可能高于后面四道墙之和。

### 墙2 认知墙（方法论词汇 + 心智模型）

现状：评价器校准、封存集已消耗、独立验收、配对区间、幂等、快照……即使信息架构重组后，用户在次级视图和拦截提示里仍会持续遇到。用户缺的不是页面入口，是**心智模型**——不理解"为什么系统要拦我"。

用户感受："它说我不能再用这批数据验证新版本了。为什么？我做错什么了？"

### 墙3 语言墙（英文界面）

现状：8 个页面是扩展 Opik 的，Opik 原生界面是英文。PRD 的验收口径是"中文页面与核心流程无英文阻断"——这个标准太弱。对编辑和教研用户，一个英文的 dataset 管理页就是事实上的劝退点，哪怕功能上"能点过去"。

用户感受："这个页面我每个字都认识，连起来不知道在哪点。"

### 墙4 成本焦虑墙

现状：三角色模型、阶段预算、token 单价、在途预留——这是给懂的人看的控制面板，不是给怕的人看的安心保证。用户最怕的是"会不会跑飞了花我几百块"。

用户感受："它说'约 439 万 token'。这是多少钱？会不会停不下来？"

### 墙5 时间墙 + 解读墙

现状：盲评工时（07 §16.4：100 来源仅判断环节约 3 小时 20 分起）；报告里的统计表述（区间下界、McNemar、W/T/L/U/X）。

用户感受："让我判断 100 组？我哪有空。"以及"'区间下界大于 0'是什么意思，是好还是不好？"

**结论**：14 个页面本身已经不是主要门槛（07 §18.1 的重组已缓解）。真正的门槛排序是：**部署 > 认知 > 语言 > 成本焦虑 > 时间**。本方案按这个排序分配投入。

## 2. 目标体验："像用普通 AI 产品"到底是什么样

### 2.1 参照标准

普通用户熟悉的 AI 产品（Kimi、豆包、ChatGPT 类）的共同特征：

1. 打开网址就能用，不装任何东西；
2. 一个输入框开始，不需要先理解概念；
3. 等待有反馈，结束有通知，关了页面也不怕；
4. 花多少钱说得清、封得住；
5. 出错给人话，不给人看堆栈。

**我们像这五条。** 但有一条明确不像：普通 AI 产品可以"生成完就完"，我们必须对"有没有变好"负责。所以第 6 条是我们自己的：

6. 任何"变好了"的说法都带证据和范围；说不清时诚实说"还看不出来"——**但这句话本身必须是大白话**。

### 2.2 目标旅程：张老师的第一次（L1 全程设计示例）

张老师从管理员那里拿到一个网址，用手机号登录。

```
首页只有一个对话框和一句引导：

  把你现在在用的提示词发给我，再贴 2—3 个真实任务的例子
  （比如一份学生作业）。我帮你看看它哪里不行，改好给你对比。
  没有提示词也行，点这里从模板开始。

  [粘贴提示词的输入框]        [从模板开始]
```

她粘贴了自己的学员点评提示词，贴了 3 份脱敏作业。

```
系统：收到。我先看看你的提示词和这 3 份作业。
      （10 秒后）我先各生成一份点评，让你看看现在的水平。

      第 2 份里，AI 把学生写对的答案判成错的。你觉得这是不是
      最要紧的问题？

      [是最要紧的问题]  [还有别的问题]  [说不上来]
```

她点了"是最要紧的问题"。

```
系统：好。我改一版试试：让 AI 先对照参考答案、再下判断，
      证据不足时不说死。

      这次改动大约花 0.3 元、1 分钟。你的花费上限是 5 元
      （可以在设置里改）。[开始改]
```

1 分钟后，出现左右两栏（不告诉她哪边是新版）：

```
  第 1 份 / 共 3 份
  ┌─────────────────┬─────────────────┐
  │  A 的点评         │  B 的点评         │
  │  （可滚动）        │  （可滚动）        │
  ├─────────────────┴─────────────────┤
  │  A 能直接用吗？  [能] [改改能用] [不能用] │
  │  B 能直接用吗？  [能] [改改能用] [不能用] │
  │  （可选）哪个更好？ [A] [B] [差不多]      │
  └───────────────────────────────────┘
```

判完 3 份：

```
系统：3 份里，有一版 2 份能直接用、1 份要小改；
      另一版 1 份能直接用。

      看起来有希望——但 3 份太少，只能当参考，不能算证明。

      [存为试用版]  [再多判几份]  [就到这]
```

她点了"存为试用版"。

```
系统：试用版已保存（标记：未独立验证）。
      你平时要点评作业时，直接来这里贴一道题，我用试用版帮你写。
      用上一两周觉得稳，再回来"考个试"，把它转成正式版。
```

**全程：没有出现"数据集、评价器、校准、封存、快照"任何一个词。** 用户做了 4 件事：贴提示词、贴作业、点"是最要紧"、各判一个"能不能用"。其余全部由系统在底层完成（种子生成、诊断卡、候选改写、匿名 A/B、账本记账——这些机制一个都没少，只是不可见）。

### 2.3 两周后的回访（升级到 L2 的设计示例）

```
系统：这个任务你已经用了 13 次，攒了 9 条真实例子
      （每次你点过"能用/不能用"的都自动记下来了）。

      要不要认真优化一轮？大概需要：你 40 分钟分几次判断
      ＋ 模型费 5 元左右。做得好的话，试用版可以转正。

      [开始认真优化]  [先看看你攒的例子]  [不用了]
```

她点了"开始认真优化"，进入 L2 向导（见 4.5 节 M5）。

## 3. 三层体验架构

### 3.1 分层定义

| 层 | 是什么 | 给谁用 | 入口 | 包含 | 隐藏 |
|---|---|---|---|---|---|
| L0 演示层 | 预置示例项目＋一份已跑完的完整验收报告 | 所有人（未注册也可看） | 落地页"先看看示例" | 演示数据、示例报告（只读）、示例对话回放 | 一切配置 |
| L1 对话层 | **产品主界面**，聊天式完成"试试看"闭环 | 普通用户（教师/编辑） | 登录即达 | 贴提示词、种子输出、指问题、匿名对比、存试用版、日常贴题 | 数据集、标准、评价器、预算工程 |
| L2 工作台层 | "认真优化"向导，即 07 §18.1 的四个入口（准备任务/查看比较/运行改进/使用与反馈） | 愿意投入一轮认真优化的用户 | 从 L1 对话中升级进入 | 三步向导、判断队列、报告、转正/回滚 | 高级 JSON、候选树、校准细节 |
| L3 实验室层 | 现有 14 页（P01—P14）原样保留 | 负责人、管理员 | 独立入口"高级模式" | 全部现有能力 | 无 |

规则：

1. **L1 是默认**。新用户登录直接进对话层，永远不需要知道 L3 存在。
2. **同一套资产**。四层用的是同一个后端、同一套 API、同一份账本（07 §21.1 的数据所有权不变）。对话层的每个按钮背后调用的就是现有接口——不建第二套产品，这是硬约束。
3. **升级是拉式的**。系统根据 07 §12 的动作资格判断"该升级了"，用一句话发出邀请（见 2.3 示例），用户点确认才进入 L2。不弹窗轰炸。
4. **L3 永远可达**。负责人需要看版本历史、审计、账本明细时从"高级模式"进入，现有页面不重做。

### 3.2 与现有方案的关系

- 07 §18.1 的"四个工作入口" = 本方案 L2，不冲突，原样落地。
- PRD 的引导模式（FR27，右侧面板贯穿多页）= 升格为 L1 主界面。BR11（对话建议是草案，点"应用"才生效）**继续作为 L1 的安全枢纽**——聊天可以说任何话，但改变配置必须走结构化卡片确认。
- 07 §12 的按动作计算资格 = L1/L2 的升级触发逻辑，服务端计算，不让聊天模型自行判定（原句保留）。
- PRD 14 页 = L3，路由保留，从主导航的"高级模式"进入。

## 4. 模块详设（M1—M10）

每个模块给出：目标、具体设计、与现有方案的衔接、验收口径。

### M1 入口与启动（拆部署墙）

**目标：普通用户从"拿到网址"到"看到第一次对比"，不装任何东西。**

设计：

1. **托管试点**（需要决策 D1）：后台跑在一台服务器上（PRD §1.1 已允许"由服务器承载后台"），管理员装一次，所有用户浏览器访问。注意这不是 PRD 排除的"面向公众的多租户 SaaS"——单组织、少量账号、不开公开注册，属于 PRD 已留的口子；若法务/数据边界有疑虑，见第 9 节风险 R-3。
2. **预置示例项目**（L0）：自带演示数据＋一份**已完成的完整验收报告**＋一段示例对话回放。用途：用户动手前 30 秒看懂"做完一轮长什么样"。示例资产全部标记演示数据，不得进入任何正式报告（沿用 07 §11 的规定）。
3. **首次运行向导**（自托管场景）：把 D11 的 start.ps1 升级为一个安装器（installer.exe）：检查/引导安装 Docker Desktop、拉镜像、起服务、创建桌面快捷方式。密钥配置内置"测试连接"按钮，失败给大白话（"这个密钥无效，去某某平台重新复制一份"）。管理员视角的向导，普通用户永远不碰。
4. **模型密钥分层**：托管模式下密钥只存在于服务器（M9）；自托管模式下密钥由管理员在 L3 配置，普通用户不可见。

验收：普通用户视角"打开网址→注册→贴提示词→看到第一次对比"≤15 分钟（含注册，不含找案例的时间）；自托管管理员视角"裸机→服务可用"≤1 小时（含 Docker 下载，按网络正常计）。

### M2 对话式主界面（拆认知墙的核心，★本方案重心）

**目标：把 2.2 节的旅程做成真实界面。用户全程不接触任何方法论词汇。**

设计：

1. **界面形态**：单页对话流＋结构化卡片。对话负责解释和推进，卡片负责确认（"是最要紧的问题 [是] [还有] [说不上来]"）。所有需要用户决策的点都用卡片，不用自由文本提问——避免用户回答格式不可解析。
2. **对话能做的事**（全部映射到现有接口）：
   - 接收提示词＋案例 → 建 P01 项目＋P03 数据（走 FR03 导入接口）；
   - 生成种子输出 → 走 P09 试运行＋统一账本（BR09 不绕过）；
   - 问"哪里最要紧" → 写入诊断卡（07 §13.2 的字段照填，用户不见字段名）；
   - 生成改写候选 → 走候选创建，身份服务端隐藏（盲评规则不变）；
   - 匿名对比 → P06 匿名 A/B 组件的简化皮肤；
   - 存试用版 → P13 的 trial 发布（FR21/BR08 的试用/正式分离不变）。
3. **对话不能做的事**（护栏，全部沿用现有规则）：
   - 不能改已发布配置（BR11：草案→用户点应用→走表单 API）；
   - 不能宣称"已验证提升"（BR12）；3 份样本的对比结论固定显示"只能当参考，不能算证明"；
   - 不能代替服务端资格判断（07 §12）。
4. **最小判断界面**（2.2 节线框）：默认只有"能直接用/改改能用/不能用"三级＋可选偏好。0—3 分量表、错误标签、证据划选**默认不出现**，点"说说哪里不行"才展开（进 L2 后再引导 richer 标注）。
5. **上下文延续**：每次回到 L1，第一屏是"接着上次：还差 2 份没判 [继续]"，永远给一个明确的下一步（沿用 07 §18.3 的单一主按钮原则）。

衔接：吸收 07 文档 T03（最短探索闭环）的大部分交付物，T03 的完成标准改为"新用户不需要评价器即可在 L1 跑完探索；全程不出现内部术语（以术语表第 5 节为准）"。

验收（并入 5 人测试 TC066 增强）：目标用户在 L1 独立完成首次探索；全程无一次求助；结束后能回答理解检查三题（见第 8 节）。

### M3 术语与文案翻译体系（拆认知墙＋语言墙）

**目标：界面主层全是人话；专业内容变成可展开的第二层，而不是消失。**

设计：

1. **术语对照表成为正式设计交付物**（第 5 节为初版 v0.1），规则：主界面只允许出现左列（业务话术）；右列（专业术语）出现在 L3 和"为什么？"解释页。新词进入界面前必须先入表。
2. **每个拦截配 30 秒解释**：所有"不能做"的状态（考卷用过了、试用版不能转正、预算到顶）统一模式＝大白话一句＋"为什么有这个规矩"链接＋下一步按钮。示例：

   > 这批例子已经用来考过 v4 了。同一份考卷再考 v5，就算分数高了也不能说明 v5 真的更好——就像背过答案再考一次。〔为什么？〕〔换一批新例子考 v5〕
3. **错误码翻译表**：07 §7 的错误协议（code/message/field_errors）在前端逐条映射为大白话＋修复入口。DATA_SPLIT_LEAKAGE →"有两条作业来自同一道题，不能一条用来改、一条用来考"。
4. **复用页 i18n 硬验收**：对 fork 的 Opik 页面套中文词典；验收标准从"无英文阻断"升格为"**L1/L2 主流程英文可见度为零；L3 高级页面英文可见页面数＝0**"（TC051 增强版）。工作量在 M0 对锁定的 Opik 版本盘点字符串量后确认，若上游 i18n 改造成本过高，回退方案是 L3 保留英文但在每页顶部加中文操作说明条。

验收：术语表评审通过；错误码翻译覆盖 100% 用户可见错误；i18n 验收按上述量化口径执行。

### M4 成本体验：单旋钮（拆成本焦虑墙）

**目标：用户只管一个数字。**

设计：

1. **新手只见一个设置**："本次最多花多少钱"（或"最多调用多少次"，单价未知时自动切换为次数模式——沿用 07 §18.5 的规则）。默认 5 元（示例值），首跑默认更低。
2. **三档预设**（数字为示例，接 M0 后按实测校准）：
   - 试试看档：≤1 元。3—5 例种子＋1 个候选＋一次对比。
   - 标准档：≈5 元。完整 L1＋几次迭代。
   - 认真档：用户自设上限，进入 L2 前的向导里给预估区间。
3. **角色预算全部折叠**：生成/评价/优化三角色、阶段额度、独立验收预留——默认由任务模板按档位自动分配，只在 L3 暴露。07 §18.5 的"预算不足给三条路（保存配置/减少候选/以后再验证）"保留。
4. **花费仪表常驻**：L1/L2 每页右上角"已花 x / 上限 y"，点击展开明细（请求数、token、按角色分）——明细给得起，但默认不打扰。
5. **到顶即停＋安抚文案**："到上限了，已完成的 3 份对比都保留着。〔提高上限继续〕〔就到这〕"。底层沿用 D08 的预算门禁与在途结算，不改。

验收：L1/L2 默认可见配置项 ≤3 个；任何时刻界面上的花费数字与账本一致（TC065 覆盖）；到顶后不再有新收费调用发出。

### M5 三步主流程（L2 向导）

**目标：把 07 §11 的双路径翻译成用户语言的三步：试试看 → 认真改 → 考个试。**

| 用户看到 | 对应现有概念 | 进入条件（用户说了什么） | 用户要投入什么 |
|---|---|---|---|
| 第一步·试试看 | 引导探索（07 §11 路径A） | 贴了提示词和例子 | 10—15 分钟，几毛到几元 |
| 第二步·认真改 | 批量优化准备＋有限搜索 | "这个任务我要长期用"或攒够例子后系统邀请 | 分几次共 30—60 分钟判断＋几元 |
| 第三步·考个试 | 独立验收（路径B） | 用户主动点"想转正" | 按样本规划，向导先给工时/费用预估，确认才跑 |

设计要点：

1. 每一步开始前显示同一格式的"本次要花什么、能得到什么、最多花多少钱"摘要卡（07 §18.5 的启动摘要简化版）。
2. **升级触发即 2.3 节的邀请卡**：系统在例子数、使用次数达到阈值时发出，用户拒绝则不重复打扰（至少间隔一周，设置里可关）。
3. 第三步"考个试"的向导里，样本规划和工时预估用 07 §16.3/16.4 的方法算，但展示为"要考 60 份左右，你大概要分 4 次每次 20 分钟；模型费约 x 元"。
4. "考完没过"的结果页固定给 M7.3 的"这轮学到了什么"。

### M6 判断减负（拆时间墙）

1. **默认三选**："能直接用/改改能用/不能用"，即 2.2 线框；量表与标签按需展开（07 §18.4 的"先两个独立判断再偏好"保留为底层逻辑）。
2. **微批次**：一次只给 5 组，判完显示进度与剩余时间预估（用该用户前几批的实际耗时滚动估计），随时可停（07 §18.4 的草稿规则不变）。
3. **判断页固化布局**：输入与参考置顶可切换、左右独立滚动、大按钮、回车＝下一组；中文输入法组合期间禁用快捷键（沿用 P06 规则）。
4. **"说不上来"永远可选**且不惩罚（BR04 的 unknown 语义照旧）。

验收：单组平均判断耗时在 5 人测试中实测记录；"改改能用"的占比可统计（它同时是提示词还差多远的一个朴素信号）。

### M7 结果与报告翻译（拆解读墙）

1. **三句话规则**：每份报告（含 L1 的迷你结论）首屏 ≤3 句大白话＋频数表述。示例：
   > 新版在 60 份真实作业上，能直接用的从 37 份提高到 51 份（修好 16 份，弄坏 2 份）。严重错误没有增加。"提升不太可能是碰运气"的完整依据〔展开〕。
2. **统计翻译表**（并入第 5 节术语表）：区间下界>0 →"不太可能是碰运气"；证据不足 →"还看不出来，例子不够"；no_improvement →"新版没比原版更好"；regression →"新版更差了"。展开层保留精确统计（W/T/L、区间、门槛），可点回原文（FR18/BR12 不变）。
3. **"没提升"页固定加"这轮学到了什么"**：展示本轮排除的假设（诊断卡 outcome）、保留原版意味着什么、下一步建议。目标是把"白花钱"的感受转成"花钱买了个确定性"。
4. **改动卡增强**：在 07 §18.7 的"改了什么—依据什么—预期—实际"之外，固定配 2—3 个真实案例的前后输出对比——用户读不懂提示词 diff，但看得懂输出变好了。

### M8 日常使用入口＋通知（留存与数据飞轮）

1. **"今天要用"页**：贴一道今天的题→当前（试用或正式）版本直接出结果→三个轻反馈钮（直接用了/改了改/没用）。改了改可选贴回修改后的文本。
2. **一键沉淀**：每次轻反馈自动进入待核验开发池（P13/FR22 的回流规则不变：不直接当 gold、不自动进封存集）。
3. **异步通知**：长任务完成、需要人来判断、预算触顶、版本可转正——发浏览器通知＋可选邮件。文案给人话："你的对比结果好了，还差 2 组没判〔去判〕"。浏览器关闭不造成"任务是不是没了"的误解（07 §18.6 的运行页规则保留）。

这一条同时解决三个存量问题：产品嵌入日常工作流（留存）、真实输入持续沉淀（冷启动数据难收集）、反馈回收不靠用户自觉（R13 的反馈覆盖率）。

### M9 模型与密钥的隐藏

托管模式：用户全程不见密钥、不见模型名（只看到"当前 AI 引擎：推荐配置"）；管理员在 L3 换模型。自托管：管理员配一次，测试连接，普通用户同样不可见。换模型＝新实验条件的提示照旧（07 §13.3 路由），但对普通用户翻译为"换了引擎，之前考的试不算数了，要重新比一次"。

### M10 帮助体系

1. 每个表单字段带"为什么问这个"一行小字（新建页 5 问尤其需要）。
2. 首次进入 L1 的引导气泡 ≤5 个，可跳过，不再出现。
3. 专业术语 hover 弹卡（术语表驱动）。
4. 全局"这是什么？"按钮：定位当前页面在三轮中的位置＋一句话解释。

## 8. 度量与验收

### 8.1 体验指标（全部为待验证目标）

| 指标 | 目标 | 测法 |
|---|---|---|
| 首次价值时间（拿到网址→看到第一次对比） | ≤15 分钟，≥4/5 人 | 5 人测试实录 |
| 独立完成率（无求助跑通 L1） | ≥4/5 | 同上 |
| 理解检查三题 | ≥4/5 全对 | 见下 |
| 默认可见配置项（L1/L2 任一屏） | ≤3 | 界面走查 |
| 主流程英文可见度 | 0 | 走查＋截图存档 |
| 管理员自托管安装到可用 | ≤1 小时 | 裸机实测一次 |

理解检查三题（5 人测试结束必问）：
1. "你现在用的是哪个版本？试用版还是正式版？"（答不出＝标识设计失败）
2. "为什么试用版不能直接当正式版用？"（考察认知墙，允许用自己的话）
3. "如果 AI 说新版提升了 16%，你信吗？为什么？"（考察用户是否内化了"要看证据和范围"）

第 2、3 题答不好不是用户的问题，是翻译层的问题——修 M3/M7，不修用户。

### 8.2 新增测试用例（建议编号 TC083—TC088，均待执行）

- TC083｜M2｜L1 全程不出现术语表右列词汇（自动化字符串扫描界面文案）。

- TC086｜M8｜"今天要用"页每次执行的输入按 FR22 规则进入待核验池，不进封存集；轻反馈不改变发布指针。
