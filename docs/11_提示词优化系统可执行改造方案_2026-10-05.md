# 提示词优化系统可执行改造方案

日期：2026-10-05。状态：待实施设计，不代表代码已完成。依据：10号审查报告、09号单机版决策、当前两版代码。所有新增文件名、API、表结构及阈值均为本方案建议；标为“现有”的位置才是已存在实现。

自评修订：执行时同时遵循[12_第一性原理自评与方案修订](12_第一性原理自评与方案修订_2026-10-05.md)。该文修正通用指标/阈值、代表性、失败口径和一次性过度建设的问题；冲突处以12号文为准。任务范围T00—T15保留，按小批交付并持续验收。

## 1. 交付目标和范围

交付一套本机运行的实验工具：对任意提示词，固定任务、评价标准、模型配置和预算，依据真实案例提出改写，在独立新案例上验证，给出可追溯的改善/退步/证据不足结论，并绑定实际采用的版本。

沿用09号决策：Windows本机、表单向导、任意提示词、不提供业务模板、不灌入示例项目。阶段一保持轻量版零第三方运行依赖；开发测试允许已有pytest。自动搜索作为后续可选能力，不使现有人工流程依赖GEPA安装。

产品主入口继续使用prompt-lab/。主版本prompt_lib/保留专业能力和旧项目，先修关键缺陷，再逐步复用共享领域函数。阶段一不合并两套数据库，不批量迁移业务项目。

开发优先级：证据正确 → 使用流程闭环 → 自动评价可信 → 搜索效率与算法。不得用“接入GEPA”替代评价与验收修复。

补充说明：主版本已有retained_alt，能保存少量备选；但备选未形成前沿父候选采样，仍不能称为GEPA搜索。

## 2. 发布里程碑

| 版本 | 用户可获得的结果 | 放行条件 |
|---|---|---|
| v0.2 可信人工实验 | 人工盲评、独立考试、正确结论、可信采用 | T00—T10完成；两版关键缺陷均有回归测试；本地恢复演练通过 |
| v0.3 自动评价与反思 | 可选机器评价、人工校准、开发/选择分工 | T11—T13完成；未校准评价器无法给确认性结论 |
| v0.4 GEPA搜索 | 同一协议下切换单次改写/贪心/GEPA | T14—T15完成；同预算对照试验有完整记录 |

“没有改善”可以通过工程验收；伪造或过度表达改善不能通过。不得将某个算法必须获胜作为验收要求。

## 3. 用户流程：每步必须形成什么产物

| 用户操作 | 必填信息 | 服务端产物与控制 |
|---|---|---|
| 贴提示词 | 正文、名称 | 不可变版本、正文哈希；可选“不可修改的规则” |
| 说清想改什么 | 一句目标、判断直接可用的标准 | 评价协议v1；没有标准只能试跑，不给确认性结论 |
| 贴例子 | 输入；参考材料可选 | 来源组、内容指纹、用途记录；参考材料与生成输入分离 |
| 看原版表现 | 每条能用/需改/不能用/未知，严重问题及说明 | 基线输出、人工评价、错误证据 |
| 生成改进版 | 选择最重要的问题；预算上限 | 修改假设、新版本、修改摘要；失败不产生假候选 |
| 比较与试用 | 两侧独立评级；偏好可选 | 探索报告；无论多显著也只推荐试用 |
| 用新例子考试 | 未参与优化的新来源；冻结协议和样本计划 | 候选绑定、配置快照、盲评、不可变报告 |
| 采用或保留原版 | 采用方式、可选说明 | 采用记录绑定报告及完整运行包；可回滚 |

2—8个例子仍适合快速探索；不要求用户首轮准备完整三分数据。只有启动自动搜索时才需要独立选择集，申请确认性结论时才需要新考试集。

界面保留“用一用”。已看过结果、已提交反馈或进入反思的日常案例默认进入开发池，不能因“来自日常使用”自动变成独立考题。需要考试时，先固定候选，再前瞻性收集尚未查看结果的新输入。

## 4. 必须统一的业务协议

### 4.1 评价结果

新增共享类型（标准库dataclass和显式校验即可）：

```text
EvaluationContext
  task_input, candidate_output, evaluation_reference
  rubric_snapshot, task_spec_hash, output_hash
  judge_snapshot_hash, purpose

EvaluationResult
  status: ok | unknown | invalid
  usability: usable | minor | unusable | unknown
  severe: true | false | unknown
  dimensions: {dimension_id: score | unknown}
  violations: [{rule_id, severity, evidence, explanation}]
  evaluator: human | rule | model
  evaluator_version, raw_result_ref, error_code
```

规则：bool不作为整数分数；维度必须符合协议，分数必须在范围内；缺项/越界/坏JSON不能成为0分或已通过。模型返回的“自信”不等于校准证据。严重问题的证据需绑定输出，引用位置可核验；证据不充分时送人工复核。

### 4.2 评价协议

每次确认性考试冻结以下字段，不能看结果后修改：

```json
{
  "protocol_version": 1,
  "primary_metric": "direct_usable_rate",
  "statistical_unit": "source_group",
  "confirmatory_sampling": "one_locked_case_per_group",
  "alpha": 0.05,
  "test": "exact_mcnemar_two_sided",
  "min_observed_gain": 0.05,
  "max_observed_severe": 0,
  "unknown_policy": "worst_case_sensitivity",
  "planned_groups": null,
  "sampling_plan_hash": null,
  "stopping_rule": "fixed_sample",
  "policy_status": "draft"
}
```

0.05提升阈值是首轮产品建议值，含义是提高5个百分点，不是通用行业标准。主指标和阈值可调整，但必须在确认性运行前冻结。planned_groups为空时允许探索，不允许声称正式验证通过。

首版以“直接可用率”为主指标，偏好作为次指标，不允许偏好抵消正确性退步。分类、数值、规则任务在v0.3增加指标适配，不引入业务提示词模板。

### 4.3 运行与采用快照

```text
ExperimentSnapshot
  project_id, baseline_version_id/hash, candidate_version_id/hash
  model_provider, endpoint, model_id, generation_params
  renderer_version, rubric_hash, evaluator_hash, protocol_hash
  dataset_manifest_id/hash, code_version, seed
  price_version, budget, credential_ref

Decision
  evidence_status: valid | insufficient | invalid | legacy_unverified
  quality: improved | worse | not_proven | inconclusive
  eligible: boolean
  reasons: [stable_reason_code]
  report_hash, policy_version

Release
  mode: verified | manual_unverified | trial
  prompt_hash, execution_snapshot_hash, report_id/hash
  actor, reason, previous_release_id, created_at
```

密钥不写入快照或导出，单独按credential_ref解析。修改全局设置只影响新运行；旧运行继续使用已固定的非密钥配置。验证通过是报告属性，“正在使用”是使用状态，两者分开。

## 5. 数据与迁移设计

### 5.1 新增逻辑表

先在轻量版落地；主版本用现有表适配同一接口。通用ID在领域层用带命名空间的字符串，避免两个数据库整数ID互相混淆。

| 表 | 核心字段和约束 | 用途 |
|---|---|---|
| schema_migrations | version主键、applied_at、checksum | 可重复安全启动，防重复迁移 |
| case_provenance | case_id主键、group_id、input_hash、reference_hash、origin、independence_status | 来源与独立性 |
| case_usage | case_id、run_id、purpose、first_exposed_at；组合唯一 | baseline/reflect/select/acceptance/usage的真实使用记录 |
| evaluation_protocols | id、project_id、version、json、hash、status | 不可变评价协议 |
| experiment_snapshots | run_id主键、snapshot_json、hash | 实验配置冻结 |
| acceptance_jobs | id、run_id、candidate_hash、manifest_hash、protocol_hash、state | 一次绑定与可恢复考试 |
| acceptance_members | job_id、group_id、case_id；job_id+group_id唯一 | 首版一来源一考题；原文/引用绑定快照 |
| acceptance_claims | project_id、group_id唯一、job_id | 防同源证据被另一确认性任务重复占用 |
| evaluation_records | id、run_id、output_id、result_json、version、supersedes_id | 追加记录，保留更正历史 |
| reports_v2 | id、job_id、snapshot_hash、decision_json、metrics_json、hash | 不可变报告 |
| release_events | id、project_id、mode、snapshot_hash、report_hash、previous_id、reason | 可回滚使用历史 |
| call_attempts | id、logical_id、attempt_no、request_hash、state、reserved/actual、phase | 统一持久账本 |

accepted group的占用以项目为边界。历史内容重复跨项目可以展示提示，不能通过拷贝项目将已有结果自动认证为全新证据。

### 5.2 迁移执行步骤

1. 新增显式数据库路径参数和环境变量，测试永远指定临时路径。禁止测试回落真实data目录。
2. 停止旧进程写入；用sqlite3.Connection.backup生成数据库备份，记录SHA256、schema版本、行数及时间。不要直接复制正在写入的WAL数据库文件。
3. 在备份副本先跑事务迁移，执行PRAGMA integrity_check和foreign_key_check；每连接启用foreign_keys。
4. 新增表与字段，不删除旧表。能重建的历史用途写入case_usage；无法证明独立性的历史数据标记legacy_unknown，只能开发使用。
5. 旧报告原文保留、标为旧协议；旧正式指针不静默撤销，但显示“历史采用，未按新协议复核”。不得自动把旧报告升级为verified。
6. 完成计数、关系、哈希检查后在业务库执行同一迁移；失败回滚整个事务。
7. 验证“旧项目能打开、原版本能使用、账本未丢、备份能恢复”。回退时同时恢复匹配的代码与数据库；升级后新写入需先导出保存，不直接丢弃。

## 7. 统计与决策的具体实现

### 7.1 先采用最容易验证的独立单位

v0.2确认性协议固定为“一来源组预先随机选一个代表输入，每侧生成一次”。选择发生在看到结果前，种子和候选列表写入manifest。重复生成另作为稳定性探索，不增加独立n。

同源多条的专业模式可做组均值配对bootstrap，但必须明确估计目标（默认每组等权），McNemar不能直接套在相关的逐条结果上。v0.2未实现组级协议时，只出探索报告或改用一组一条协议，不伪装已支持。

### 7.2 固定频数和公式

对两边均可评价的独立配对，a=双方可用，b=原版不可用/新版可用，c=原版可用/新版不可用，d=双方不可用。

```text
n_known = a+b+c+d
baseline_rate_known = (a+c)/n_known
candidate_rate_known = (a+b)/n_known
gain_known = (b-c)/n_known
p = min(1, 2 * sum(C(b+c,k), k=0..min(b,c)) / 2**(b+c))
b+c=0 时 p=1
```

主显示分母为计划完成的全部配对N，不能只显示known率。每侧分别计算usable、unusable、unknown：下界=usable/N，上界=(usable+unknown)/N。minor在“直接可用率”中为不可直接用，但单独显示。

缺失敏感性：已知单侧状态保持不变；所有未知的新版取0、原版取1，构造最不利改善情景，计算gain与McNemar。最不利情景不能支持改善则不允许verified。这样unknown不会因删分母而制造提升；并保留最有利情景用于解释。

报告展示配对bootstrap区间（20,000次、固定seed、成对抽样）作为辅助；退化/小样本区间明确标注。v0.2采用资格以预先固定的精确配对检验、效应阈值和门槛为准，不以退化bootstrap下界作唯一证据。这里证明的是统计方向改善且观察幅度达到阈值；若要声称“真实提升至少5个百分点”，需要另行针对该效应界限设计区间/检验。

### 7.3 唯一采用规则

依次执行：快照匹配 → 数据独立与协议冻结 → 固定样本计划完成 → 评价有效/人工复核完成 → 候选严重错误0且严重状态无未知 → 最不利缺失情景gain≥协议阈值且双侧p<alpha → eligible=true。

若观察到严重错误，直接不合格；若证据不足，inconclusive；若退步有足够证据，worse；其余not_proven。保留原版为正常结果。

严重错误零观察不等于零风险。独立来源数n下可展示单侧95%零事件上界1-0.05**(1/n)，并标明独立同分布等适用前提；不能拿输出条数替代独立来源数。
