# 第一性原理自评与实施修订

2026-10-05。本文是对11号执行方案的自我审查及修订，不是效果验证报告。发生冲突时以本文为准。工程任务范围T00—T15保留，但实现以当前代码、实际用户价值和证据为准，不机械照搬建议表结构。

## 1. 是否可笑

核心思路合理：将“改一句提示词觉得更好”转为“明确目标、记录改动、比较结果、用新数据验证”。但原方案存在形式化过度的风险：两套产品同时维护、一次提出12张新表、16任务按直线做完才试点，将一个本机个人工具推向研究平台。没有真实价值反馈，做出合规齐全但没人用的系统也是失败。

因此必须分批交付可用行为；复用现有runs、outputs、ledger、reports等表，只有现有存储无法表达事实时新增表。数据库合并仍不做。共享只抽取已经有两个调用方的确定性规则。

## 2. 是否有效

能提高实验可信度、减少错误采用，有直接可复现的代码缺陷作为依据；能否提高实际任务质量仍是待检验假设。工程正确、评价可信、搜索有收益、日常使用有价值是四个不同结论，不能拿离线Mock闭环证明真实质量提升。

改写不是必然改善；当任务缺资料、模型能力不足、评价标准错误时，提示词无法补救。有效系统应允许保留原版、修改数据/工具/任务定义，并识别成本超过收益的情况。

## 3. 第一性原理

提示词不是独立性能指标。输出Y由任务输入X、提示词P、模型M、工具T、采样随机性R共同产生。目标是特定任务分布D上的业务效用E[U(Y,X)]，受严重风险、成本和时间约束。修改P的价值是相同执行条件下候选与基线的效用差，而非提示词写得更长、更规范或模型解释更好看。

四个必要环节：

1. **测量**：可观察的质量/人工工作量能近似业务效用。评价规则错，搜索只会更有效地钻规则漏洞；人工评分也须说明评价者和适用范围。
2. **比较**：同输入、同模型、同参数、交错执行、匿名评价尽量隔离改写效果。固定温度不保证完全确定；云端模型也可能漂移。
3. **搜索**：失败输出与参考资料提供信息，模型提出新的规则假设；每个假设必须重新执行，解释不是因果证明。
4. **泛化和选择**：反复挑选候选会过拟合。选择集用于寻找候选，新的封存样本用于检验；评估能力和来源代表性决定结论能推广多远。

工程的价值是让上述环节可复现、可暂停、可审计，不能代替统计独立性或任务代表性。GEPA只是可替换的搜索策略；先把错误打分的系统接GEPA，可能加速错误优化。

| 工作量估计缺证据 | 原人日只是规划占位，不作为交付承诺；用实施记录与剩余任务评估进展 | 全部 |
| 12张新表先于行为需要 | 随能力增量迁移；复用现有表和JSON快照，避免同事实双存储。迁移依旧需事务和恢复验证 | T02/T03/T07/T08 |
| 同一提示词可以用新样本反复考试，每次都按p<0.05后挑显著结果 | 这会累积误报。正式考试共享固定5%累计预算，按预先固定的几何α分配：第i次阈值为0.05/2^i，所有轮次之和不超过5%；中断考试也占一次。次数由服务端事务计算，冻结进协议并在报告显示；过期页面不能沿用宽松阈值 | T06/T15 |
| 已确认的人类严重金标只读锁定，纠错无产品流程 | 通过追加仲裁记录和supersedes链更正；旧记录不改写，已被替代的金标不能发起新审计，引用旧金标的准入实时失效 | T11/T15 |

2026-10-05复核发现并修复了上表最后一项。采用几何α分配而非简单的0.05/i，因为后者的无限和发散，不能控制任意多轮考试。回归场景为：7个独立来源全改善时双侧精确p=0.015625，可在首轮阈值0.025下通过；同一提示词第二轮即使又在7个新来源全改善，阈值降至0.0125，不能再次通过。该策略控制新版策略下同一提示词未来反复考试的累计误报概率；不同提示词之间的选择、重复prompt建档及历史版本产生的旧报告不因此获得追溯性保证。旧冻结协议不满足新版本校验，不能作为新一轮验证采用证据。

严重金标争议修复后使用新增的不可变子记录，不覆盖初次评审。每条仲裁绑定前一金标哈希、仲裁人、原因及原文证据；新审计只接受最新叶子记录，已绑定旧金标的历史审计会在重新验据时失败关闭。该机制保证记录链完整，不替代真正独立、具备领域能力的仲裁人判断，也不证明严重规则本身正确。

重复检验防护的产品边界不同：主版本一个项目只能绑定一次封存考试，并消耗该项目封存集；轻量版允许使用新来源继续测试，因此用固定几何α序列分配未来检验预算。两种机制都只对各自的项目/提示词范围生效，跨项目、重复建档与历史旧结果的选择不纳入同一错误率保证。

## 5. 价值验证及完成要求

除软件测试，还须真实任务数据：固定一个业务目标，保留原始输入输出、人工判定、修改时间和费用，比较原版/一次改写/多轮优化。若无法获取足够独立新数据，报告不足，不放宽“验证通过”定义。

评价对象必须明示“在这类任务、这位评价者/评价器、这个模型配置和采样范围下”。总体可用率外同时显示修复/退步、严重问题、unknown、修改时间、每个可用结果成本。相同预算对照只证明预算条件下的效果，成本收益需看实际消耗。

原方案T00—T15仍是完整待实施目标。交付记录逐项给出代码、测试、状态，未有真实数据的T15保持未验证，不因Mock通过宣称全部完成。连续工程工作先执行；需要真人判断或未授权的真实付费调用时才请求必要信息。

## 6. 首批实施范围

T00：临时数据、随机端口、自行管理模拟供应商、统一离线验证入口。

T01：全退步分支不崩溃、偏好不能掩盖可用性退步、未知不伪装改善、发布绑定候选与报告、所有门槛执行、人工自行采用留独立未验证证据。

随后按T02—T15继续，完成前不将整体目标标记达成。
