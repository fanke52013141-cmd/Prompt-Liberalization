# 提示词优化实验室（Prompt Liberalization）· 本地版

根据《提示词自优化系统_需求与开发方案_2026-09-27》（v2.0）构建的**本机 Windows 单机版**系统，
实现 PRD 定义的完整业务闭环：

> 案例 → 评价标准 → 评价器 → 基线 → 优化 → 独立验收 → 采用/回滚 → 使用反馈

面向在 Windows 浏览器中工作的教师、教研、编辑和内容负责人。单负责人使用，仅绑定本机回环地址，
不启用公网访问。**所有演示数据均明确标注 demo，不构成真实效果结论。**

## 五步流程主线（优化1.0，2026-09-27 改造）

依据 [docs/优化1.0.md](docs/优化1.0.md) 完成一阶段改造，界面以连续流程为主线：

**准备材料 → 确认怎么评 → 原始测评 → 自动优化 → 验证与使用**

- **自由任务定义**：四种业务模板降级为可选示例；用户自定义输入字段、评价专用字段与优化目标
  （界面为逐行输入框，系统自动拼装任务结构；字段名留空按显示名自动生成）
- **专家意见 → 检查项**：保留专家原话与备注原文；问题描述/期望/检查方式/影响程度/状态结构化；
  标签支持定义、停用与同义合并（合并关系可追溯）
- **ABCD 评级**：自定义评级规则（版本化，历史不被重新解释）；无法判断/尚未评价单独记录；
  按"原问题改善 + 新增问题"两个维度同时展示
- **优化器完整证据输入**：失败案例的完整输入/输出/专家意见/原来正确的代表案例/历史轮次全部进入优化器
  （不再只发案例编号与低分维度）；改写失败（坏JSON/超长/空正文）**显式报告，无固定兜底文本**
- **底线检查**：候选保留需通过"原有正确案例不得回退、严重错误不得增加"；保留/淘汰均记录具体依据；
  连续无改善、达到目标、达到轮数上限、主动停止、预算耗尽均为明确停止原因
- **人工参与模式**：可选择每轮等待人工评价后继续；离开页面不取消运行
- **问题级统计**：独立验收报告按"完全解决/部分解决/未解决/无法判断"统计问题项，
  并给出 ABCD 分布与证据范围（优化样例 vs 独立封存样例，不混用）
- **历史兼容**：旧项目、旧配置、旧报告与新流程共存；旧库自动补列迁移，不覆盖历史数据

原有的 P01–P14 功能模块（标注、评价器校准、实验配置等）保留为"高级功能"入口。

## 快速开始

```powershell
# 1) 安装依赖（Python 3.11+）
pip install -r requirements.txt

# 2) 启动（推荐，含启动诊断；等效手动命令见下）
powershell -ExecutionPolicy Bypass -File scripts\start.ps1

# 或手动启动
python run_server.py
```

浏览器打开 **http://127.0.0.1:8620** （仅本机可访问）。

其他脚本（PowerShell）：

| 脚本 | 作用 |
|---|---|
| `scripts\start.ps1` | 诊断 + 后台启动（不弹多个终端） |
| `scripts\stop.ps1` | 停止服务（**不删除数据**） |
| `scripts\doctor.ps1` | 环境/数据/账本一致性诊断 |
| `scripts\backup.ps1` | 备份数据库（含 SHA256 校验清单） |

## 内置离线模拟供应商

系统内置**确定性离线模拟供应商**（连接 `conn_mock`），无需任何 API Key 即可跑通全部流程——
模拟生成器按提示词特征产出输出、模拟评价器按输出特征打分，构成自洽的闭环（所有结果为演示性质）。

接入真实模型：进入 **P14 设置** → 添加 OpenAI 兼容连接（智谱 / DeepSeek / OpenAI 等），
填写 Base URL、模型名与 API Key（密钥只保存在本机数据库，界面只显示"已配置"，导出与日志不含密钥）。
随后在新实验配置中选择该连接即可。

## 关键业务规则（服务端强制）

- **BR01** 生成请求只含 `runtime_input` 白名单；`evaluation_only` 永不出站（测试用哨兵字符串验证）
- **BR02** 冻结组件不可原地改写；候选改冻结段在任何收费请求发出前被拒
- **BR05** 同一来源分组跨开发/选择/封存集合 → 冻结被阻止（防数据泄漏）
- **BR06** 测试明细一次性消耗：用于改写后不能再作为独立验收证明
- **BR09** 生成/评价/优化所有角色调用统一进账本：预留 → 调用 → 结算；sent_unknown 保留潜在费用
- **BR10** 评价标准/模型变化 → 评价器 stale；不能用于确认性验收
- 金额硬预算要求所有角色模型已有核实单价，否则只允许 token 上限模式
- 搜索预算耗尽不占用独立验收预留；无提升是合法结果（保留基线，不显示"成功"）

## 统计口径（与验收方案 FX07/FX08 一致）

- 精确 McNemar：FX07 黄金值 b=20/c=4 → p≈0.00154388（测试断言）
- 分组成组重采样配对 bootstrap（不把同源多次输出当独立来源）
- 缺失值界限（80条=50可用/20不可用/10未知 → 62.5%–75%，非 50/70）
- 零严重事件 → 单侧 95% 上界（n=100 约 2.95%），**不宣称真实零风险**

## 与需求文档的关系

文档主线是"扩展 Opik + GEPA"，依赖 Docker/Linux 容器。本机无 Docker 环境时按文档 02 第 11 节的
降级思路，将同一业务闭环实现为自包含本地系统；优化器接口形态与 GEPA 对齐（候选集/反思反馈/预算回调），
供应商接口与 OpenAI 兼容协议对齐，后续可替换为真实引擎。映射与偏差详见
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)，验证结果见 [docs/VERIFICATION.md](docs/VERIFICATION.md)。

## 已知限制

- 单机单用户；多人远程访问需先补身份与权限（文档 1.3 节，V1 范围外）
- 优化器为确定性反思式改写（GEPA 式接口），未接真实 GEPA SDK；接真实模型后在 M0 验证
- 封存测试原文保存在本机受限表中，阻止应用层误用，不防拥有管理员权限的人直接读磁盘
- 统计实现以固定种子记录 golden 结果；更换随机库需重新记录（不把误差当优化效果）
